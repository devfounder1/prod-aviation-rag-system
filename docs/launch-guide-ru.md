# Инструкция для запуска BUTUZIK AI

Это пошаговая инструкция для Windows x64: как из выданного исходного архива подготовить полную папку программы, перенести её на флешке и запустить на другом компьютере без интернета. Программировать для выполнения инструкции не нужно. Установку системных компонентов и настройку компьютера организации выполняйте вместе с её администратором.

**Главное перед началом.** Текущий исходный ZIP ещё нельзя передавать как готовую программу. Сначала на Windows-компьютере с интернетом нужно собрать в одну папку Python, интерфейс Flet, Ollama, модели и два образа для обработки документов и запуска тестов. Готовую папку затем проверяют на целевом компьютере без сети. Одного файла BUTUZIK.AI.exe недостаточно.

Дата инструкции — 20 ноября 2026 года. Приложение называется BUTUZIK.AI; создатель приложения — Demashov Michail Sergeevich. Qwen и другие модели Ollama — отдельные компоненты.

## 1 С какого места начинать

**Если у вас только ZIP с App и Tools.** Начните с раздела 2 и выполняйте разделы 3–17 по порядку. Это подготовка полной программы. Понадобится компьютер Windows x64 с интернетом, свободное место и согласованная библиотека ГОСТ от разработчика.

**Если вам уже передали полную проверенную папку.** Сборку повторять не требуется. Перейдите к разделу 18 для первого запуска на другом ПК, затем к разделу 19 для ежедневной работы. На новом ПК всё равно надо подготовить Docker и WSL, если нужны ГОСТ и выполнение тестов.

**Если вы хотите просто пользоваться программой.** Попросите ответственного за подготовку выполнить разделы 3–18. После этого обычный запуск занимает несколько действий из раздела 19. От пользователя не требуется каждый день скачивать модели, вводить команды сборки или запускать установщики.

Раздел 20 объясняет кнопки и проверку функций; 21 — где лежат файлы; 22 — резервные копии; 23 — ошибки; 24 — когда комплект можно отдавать. В Word нажмите Ctrl+F и введите название нужного раздела; заголовки также видны в области навигации.

## 2 Что именно надо собрать

Слово «собрать» здесь означает подготовить компоненты и запустить готовый сценарий, который скопирует их в новую папку. Писать код приложения или самостоятельно создавать EXE не требуется: сценарий делает это за вас. До его запуска нужно получить перечисленные ниже файлы.

| Компонент | Простое объяснение | Где появится после сборки |
|---|---|---|
| Исходники приложения | Логика чата, поиска, файлов и ГОСТ | App |
| Python 3.12 x64 и библиотеки | Среда, которая выполняет приложение | Runtime |
| Flet 0.28.3 для Windows | Окно, кнопки и поля ввода | Flet |
| Ollama для Windows amd64 | Локальный сервер выбранной модели | Ollama |
| Модели Ollama | Веса текстовой и vision модели | Models/ollama |
| Модели поиска и голоса | Локальные данные для поиска и распознавания речи | Models/huggingface/hub |
| Библиотека редакций ГОСТ | Архив предоставленных PDF и извлечённых страниц | App/data/standards_library/v1 |
| Два образа Docker | Готовые Linux среды для Word и Python тестов | Images |
| Launcher EXE | Запускает Python и приложение из этой папки | BUTUZIK.AI.exe |

Docker Desktop и WSL устанавливаются в Windows отдельно. Они не превращаются в часть EXE при копировании папки. Microsoft Word на рабочем ПК для самого контейнерного преобразования не требуется; он удобен для просмотра и ручной правки результата DOCX.

У программы две стадии. Во время **подготовки** ответственный человек явно скачивает компоненты. Во время **обычной работы** приложение использует уже подготовленные локальные файлы и не должно докачивать недостающее. Компьютер, на котором готовят папку, и компьютер пользователя могут быть разными.

## 3 Проверьте компьютер и свободное место

1. Нажмите Win+I, откройте «Система», затем «О системе». Найдите «Тип системы». Нужны 64-разрядная Windows и процессор x64. ARM64 и 32-разрядная Windows в этот комплект не входят.
2. Нажмите Win+R, введите winver, нажмите Enter. Запишите редакцию, версию и сборку Windows. Для нового развёртывания предпочтительна поддерживаемая Windows 11. Для Windows 10 проверьте поддержку конкретных версий Docker и Ollama у поставщиков.
3. В «О системе» посмотрите установленную оперативную память. Для Qwen 14B разумно планировать от 32 ГБ; это оценка, а не гарантия. При 16 ГБ может потребоваться меньшая модель и отдельная проверка качества. Контекст, vision, Docker и другие программы тоже занимают память.
4. Откройте «Этот компьютер». Проверьте свободное место на диске подготовки и на диске целевого ПК. Заранее выделите ориентировочно 80–150 ГБ, затем уточните объём по фактическим компонентам. Потребуется место и под исходные загрузки, и под собранную копию, и под хранилище Docker.
5. Откройте Диспетчер задач сочетанием Ctrl+Shift+Esc. В разделе «Производительность», «ЦП» найдите «Виртуализация». Для Docker с WSL она должна быть включена. Если выключена, попросите администратора настроить BIOS или UEFI по инструкции производителя компьютера.

Видеокарта NVIDIA может ускорить генерацию, но не является гарантией скорости или достаточной памяти. Результат зависит от модели, драйвера и VRAM. Драйвер и необходимые системные библиотеки устанавливают до переноса в закрытую сеть. Наличие 8 ГБ, достаточных для минимальных требований Docker, не означает, что хватит памяти для нашей модели.

**Результат раздела:** известны версия Windows, x64, объём RAM и диска; виртуализация включена. Если компьютер не соответствует требованиям, не переходите к загрузке десятков гигабайт моделей.

## 4 Как вводить команды и не запутаться

1. Нажмите кнопку «Пуск», наберите Windows PowerShell и откройте найденное приложение. Для большинства команд нужно обычное окно. Только там, где прямо написано «от имени администратора», нажмите по найденному приложению правой кнопкой и выберите этот пункт.
2. Вставьте команду в окно с помощью Ctrl+V или правой кнопки мыши. Нажмите Enter. Дождитесь окончания и возвращения строки приглашения, прежде чем вводить следующую команду.
3. Если в инструкции несколько команд показаны отдельными строками, выполняйте их по очереди. Исключение — целый блок со скобками или специальными отметками начала и конца: его копируют полностью, как сказано рядом с ним.
4. Копируйте содержимое примера без рамки, подписи «powershell» и без строки приглашения PS C:\...>. В командах нужны прямые кавычки ' и ", как в примерах. Не заменяйте их типографскими «ёлочками».
5. Если появилось приглашение >>, PowerShell ждёт завершения команды: обычно не закрыта кавычка или скобка. Нажмите Ctrl+C один раз, затем вставьте весь блок заново.
6. Ошибка или красный текст означает, что надо прочитать сообщение и проверить этот шаг. Не продолжайте вводить все оставшиеся команды подряд. Типичные случаи разобраны в разделе 23.

Путь C:\Build означает папку Build на диске C. Путь с пробелами пишут в кавычках. Знак & перед путём к EXE означает «запустить эту программу»; это часть команды. Команда Set-Location меняет текущую папку, Test-Path проверяет наличие файла, а True означает «есть», False — «нет».

Переменные, начинающиеся с $, существуют в текущем окне. После закрытия PowerShell их надо определить заново. В инструкции по возможности используются полные пути, чтобы не зависеть от открытой папки.

Перед сохранением файлов через Блокнот включите расширения в Проводнике: «Вид», «Показать», «Расширения имён файлов» в Windows 11; в Windows 10 соответствующий флажок находится на вкладке «Вид». Это помогает отличить test.py от test.py.txt.

## 5 Создайте папки подготовки и распакуйте архив

Дальше используется единый пример C:\Build. Если у вас нет права создавать папку в корне C, согласуйте другой доступный путь и последовательно замените C:\Build во всех командах. Не используйте Program Files, сетевой диск или папку синхронизации OneDrive.

1. Откройте Проводник и создайте C:\Build. Внутри создайте папки Downloads и Installers. В Downloads сохраняйте архивы компонентов; в Installers — установщики для целевого ПК.
2. Нажмите правой кнопкой по полученному исходному ZIP и выберите «Извлечь всё». Дождитесь распаковки. Не запускайте сценарии прямо внутри ZIP.
3. Найдите папку, внутри которой одновременно лежат App, Tools и ASSEMBLY_REQUIRED.txt. Переместите именно эту папку в C:\Build и назовите kit. Должны получиться C:\Build\kit\App и C:\Build\kit\Tools, без дополнительной папки между kit и App.
4. В PowerShell выполните следующие проверки по одной:

```powershell
Test-Path 'C:\Build\kit\App\prilozhenie.py'
Test-Path 'C:\Build\kit\App\uv.lock'
Test-Path 'C:\Build\kit\Tools\Build-Windows.ps1'
```

Все три ответа должны быть True. Если один False, откройте Проводник и исправьте вложенность. Частая ошибка — путь C:\Build\kit\имя_архива\App вместо C:\Build\kit\App.

Дальнейшие папки будут появляться по мере подготовки: uv, cpython312, flet, ollama, ollama-models, hf-hub и standards-v1. Готовую программу сценарий создаст отдельно в C:\Build\BUTUZIK-AI-Windows-x64. Эту последнюю папку заранее создавать не надо.

Модели загружаются отдельными командами из разделов 10–11. Архив standards-v1 нужно получить от разработчика или ответственного за библиотеку: он не включён в публичный исходный ZIP. Произвольная папка с PDF не заменяет этот подготовленный архив.

## 7 Подготовьте WSL и Docker

Этот раздел выполняется на подготовительном ПК, а позднее проверяется и на целевом. [Документация Docker](https://docs.docker.com/desktop/setup/install/windows-install/) определяет поддерживаемые версии Windows, требования к WSL и лицензированию. Согласуйте установку в организации заранее.

1. Откройте PowerShell от имени администратора. На совместимой Windows с интернетом для установки WSL без отдельного Ubuntu выполните:

```powershell
wsl --install --no-distribution
```

2. Если Windows просит перезагрузку, сохраните работу и перезагрузите ПК. Затем проверьте WSL в новом окне:

```powershell
wsl --version
```

Должен появиться номер версии. Требуемый минимум уточните на странице Docker для выбранного выпуска. Если установлена старая версия, на подготовительном ПК с сетью выполните wsl --update и повторите проверку.

3. Запустите официальный Docker Desktop Installer. Выберите WSL 2, если установщик предлагает выбор. Завершите установку и нужную перезагрузку. Откройте Docker Desktop через «Пуск», примите условия, если они согласованы, и дождитесь запуска движка.
4. Docker должен работать с Linux containers. Если меню предлагает «Switch to Windows containers», сейчас выбран Linux — это подходит. Если предлагает «Switch to Linux containers», выберите этот переход.
5. Закройте и заново откройте PowerShell после установки. Выполните:

```powershell
docker version
docker info --format '{{.OSType}}'
```

В первой команде должны отображаться Client и Server; во второй ожидается linux. Отсутствие Server означает, что движок ещё не готов. На этом шаге не требуется docker run hello-world: он может дополнительно скачивать образ.

**Для целевого ПК без интернета:** заранее сохраните установщик Docker и подходящий WSL MSI x64. Администратор устанавливает MSI и при необходимости включает компонент VirtualMachinePlatform; это описано в [офлайн установке WSL](https://learn.microsoft.com/en-us/windows/wsl/install#offline-install). Для включения компонента в окне администратора используется:

```powershell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

После изменения нужна перезагрузка. Параметр /online здесь означает текущую установленную Windows, а не требование доступа к интернету. Если выбранной системе не хватает компонентов Windows, администратору может понадобиться подходящий локальный установочный источник. На неподготовленном закрытом ПК нельзя рассчитывать, что WSL установится только из папки нашего приложения.

**Результат раздела:** Docker Desktop запущен, команда показывает linux. Для первого офлайн переноса установка системных компонентов согласована и подготовлена.

## 8 Подготовьте uv и полный Python

1. Распакуйте ZIP uv из раздела 6. Найдите uv.exe и положите его в C:\Build\uv. Если архив создал вложенную папку, перенесите её содержимое так, чтобы получился файл C:\Build\uv\uv.exe.
2. Откройте обычный PowerShell. Добавьте этот каталог только в PATH текущего окна и проверьте версию:

```powershell
$env:Path = 'C:\Build\uv;' + $env:Path
uv --version
```

3. Установите полный управляемый Python 3.12 x64. Это явная загрузка на стадии подготовки. Затем найдите его расположение:

```powershell
uv python install 3.12
$PythonExe = (uv python find --managed-python 3.12).Trim()
$PythonRoot = Split-Path $PythonExe -Parent
& $PythonExe -c 'import sys; print(sys.version); print(sys.executable)'
& $PythonExe -c 'import platform; print(platform.machine())'
```

Ожидается версия 3.12 и архитектура AMD64 или другое подтверждение x64. Если отображается ARM64, выбран неподходящий компьютер или интерпретатор.

4. Скопируйте полный найденный каталог в отдельную папку. C:\Build\cpython312 ещё не должна существовать. Если она уже есть от предыдущей подготовки, сначала выясните её содержимое; не объединяйте разные версии вслепую.

```powershell
Copy-Item -LiteralPath $PythonRoot -Destination 'C:\Build\cpython312' -Recurse
$PreparedPython = 'C:\Build\cpython312\python.exe'
& $PreparedPython -c 'import sys; print(sys.version); print(sys.executable)'
```

5. Проверьте отсутствие признака виртуального окружения:

```powershell
Test-Path 'C:\Build\cpython312\pyvenv.cfg'
```

Здесь нужен False. Нельзя передавать сборщику .venv, Miniconda с другого компьютера или macOS Python. Папка cpython312 должна содержать настоящий python.exe и его стандартные библиотеки. Минимальный embeddable ZIP без подготовленных зависимостей для этого алгоритма не используйте.

**Результат раздела:** работают uv и C:\Build\cpython312\python.exe. При открытии нового окна снова выполните строку добавления C:\Build\uv в PATH; постоянные системные настройки менять не обязательно.

## 9 Распакуйте Flet

1. Откройте релиз Flet 0.28.3 из раздела 6 и скачайте flet-windows.zip.
2. Распакуйте его. Найдите каталог, непосредственно содержащий flet.exe и соседние ресурсы, и скопируйте весь этот каталог как C:\Build\flet. Не переносите только exe.
3. Проверьте:

```powershell
Test-Path 'C:\Build\flet\flet.exe'
```

Ожидается True. Сохраните DLL и папку data, если они присутствуют в выпуске, со всей исходной структурой. Проверьте, что не получилось C:\Build\flet\flet\flet.exe.

Сборщик сверит переданный номер 0.28.3 с Python-пакетом. Эта сверка не устанавливает происхождение произвольного exe. Скачивайте клиент из соответствующего официального релиза и запишите его источник. При обновлении lock-файла версию Flet нужно пересматривать, а не автоматически оставлять этот номер.

## 10 Подготовьте Ollama и две модели

**Окно А будет сервером, окно Б — местом ввода команд.** Окно А оставляйте открытым, пока загружаются модели. Если в трее уже работает другая Ollama, согласуйте её остановку: два сервера не могут одновременно занять порт 11434. Не завершайте чужую рабочую службу без согласования.

1. Распакуйте полный ollama-windows-amd64.zip в C:\Build\ollama. Проверьте наличие C:\Build\ollama\ollama.exe. Сохраните все соседние библиотеки; дополнительные GPU-компоненты зависят от оборудования и выпуска.
2. В обычном PowerShell — окне А — выполните строки ниже. Папка моделей отделена от установленной в Windows Ollama:

```powershell
$env:OLLAMA_MODELS = 'C:\Build\ollama-models'
$env:OLLAMA_HOST = '127.0.0.1:11434'
$env:OLLAMA_NO_CLOUD = '1'
& 'C:\Build\ollama\ollama.exe' serve
```

Окно занято сообщениями сервера — это нормально. Если увидели ошибку занятого адреса, вернитесь к проверке другой службы, а не меняйте порт на случайный.

3. Откройте второе обычное окно PowerShell — окно Б. Выполните команды загрузки с интернетом по очереди и дождитесь завершения каждой:

```powershell
$env:OLLAMA_HOST = '127.0.0.1:11434'
& 'C:\Build\ollama\ollama.exe' pull qwen2.5:14b
& 'C:\Build\ollama\ollama.exe' pull qwen2.5vl:7b
& 'C:\Build\ollama\ollama.exe' list
```

В списке должны быть обе модели с точными именами. Первая отвечает на текст и вызывает инструменты; вторая анализирует изображения, не меняя выбранную модель GUI. Качество работы инструментов зависит от выбранной модели.

4. Убедитесь в Проводнике, что в C:\Build\ollama-models появились manifests и blobs. Переносить нужно обе папки целиком. Наличие файлов в обычной папке профиля пользователя вместо этого каталога не подходит для приведённых путей сборки.
5. Когда все загрузки завершены, вернитесь в окно А и нажмите Ctrl+C один раз. Дождитесь остановки сервера перед копированием моделей при сборке.

**Если памяти мало:** можно отдельно подготовить меньшую локальную текстовую модель, но после сборки нужно изменить LLM_MODEL_NAME в App\.env и повторить все проверки. Простое переименование файлов весов ничего не меняет. В этой инструкции базовый комплект рассчитан на две указанные модели; оценка памяти дана в разделе 3.

Описание Windows сервера и состава standalone ZIP: [Ollama для Windows](https://docs.ollama.com/windows).

## 11 Подготовьте модели поиска и голоса

Для поиска по вашим документам нужны отдельные локальные файлы, даже если Qwen уже скачан. Обязательная модель поиска — intfloat/multilingual-e5-small. Для ранжирования используется BAAI/bge-reranker-v2-m3. Для голосового ввода подготовьте Systran/faster-whisper-base и Systran/faster-whisper-small. Ниже загружаются все четыре, чтобы комплект не зависел от будущей сети.

1. В обычном PowerShell с интернетом подключите uv в PATH, если это новое окно, затем установите помощник загрузки в подготовительную копию Python:

```powershell
$env:Path = 'C:\Build\uv;' + $env:Path
uv pip install --python 'C:\Build\cpython312\python.exe' huggingface-hub
```

2. Только в этом подготовительном окне уберите запрет загрузок, если он ранее был установлен. Это не меняет офлайн-политику рабочего приложения:

```powershell
Remove-Item Env:HF_HUB_OFFLINE -ErrorAction SilentlyContinue
Remove-Item Env:TRANSFORMERS_OFFLINE -ErrorAction SilentlyContinue
```

3. Вставьте целиком следующий блок: от $download до последней команды. Строки с @' и '@ — служебные ограничители текста для Python; не добавляйте пробелы перед закрывающей строкой '@.

```powershell
$download = @'
from huggingface_hub import snapshot_download
repos = [
    'intfloat/multilingual-e5-small',
    'BAAI/bge-reranker-v2-m3',
    'Systran/faster-whisper-base',
    'Systran/faster-whisper-small',
]
for repo in repos:
    print('Downloading', repo, flush=True)
    snapshot_download(repo, cache_dir='C:/Build/hf-hub')
print('DOWNLOADS COMPLETE', flush=True)
'@
& 'C:\Build\cpython312\python.exe' -c $download
```

Дождитесь DOWNLOADS COMPLETE. Если блок сообщает об ошибке связи, устраните её и повторите загрузку: уже скачанные части кеша обычно используются повторно. Для этих публичных моделей не требуется переносить личный токен авторизации.

4. Откройте C:\Build\hf-hub. Должны появиться каталоги, начинающиеся на models--intfloat, models--BAAI и models--Systran. Внутри кеша сохраняются refs, snapshots и blobs. Не выбирайте из них на глаз один файл и не меняйте имена папок.

Сборщик принимает весь hf-hub и копирует содержимое ссылок в переносимую папку. После этого надо проверить реальную загрузку моделей на целевом ПК. Устройство эмбеддингов в Windows-профиле задано CPU; Apple MPS для Windows использовать нельзя. Подробности загрузчика: [Hugging Face Hub](https://huggingface.co/docs/huggingface_hub/guides/download).

## 12 Получите подготовленную библиотеку ГОСТ

1. Попросите разработчика передать **только согласованный каталог v1** из data/standards_library/v1 текущего проекта. Нужны исходные PDF, извлечённые страницы и служебные записи этого архива, с сохранением внутренней структуры.
2. Положите содержимое v1 в C:\Build\standards-v1. Если внутри standards-v1 оказалась ещё одна папка v1, откройте её: сборщику нужен именно каталог с содержимым архива, а не его дополнительная обёртка.
3. Сверьте с передающим человеком, что архив соответствует реестру App\standards\library.json именно этой версии программы. В текущем реестре зарегистрированы 12 точных предоставленных редакций.

**Если этого каталога нет, полная подготовка по этой инструкции пока не закончена.** Не создавайте пустую папку и не подменяйте издание случайным PDF из интернета. Список в library.json не содержит сами PDF, а каталог standards — это правила и реестры, не архив исходных стандартов.

Не копируйте весь data разработчика: там находятся его чаты, индексы и другая личная информация. Право передачи PDF и использование конкретных редакций согласуются отдельно. Новые ГОСТ не применяются ко всем документам автоматически: действующий профиль оформления остаётся частичным.

## 13 Подготовьте два образа Docker

Образ — это готовая среда с установленными программами. Один нужен для DOC и DOCX, другой — для запуска Python и pytest. На этапе подготовки команды могут обращаться к интернету. При обычной работе используются только уже существующие локальные образы.

1. Убедитесь, что Docker Desktop работает и проверка из раздела 7 показывает linux.
2. В обычном PowerShell перейдите в App исходного комплекта:

```powershell
Set-Location 'C:\Build\kit\App'
```

3. Соберите документный образ и дождитесь возврата приглашения. Затем отдельно соберите образ тестов:

```powershell
$docRecipe = 'document_runtime/Dockerfile'
docker build --platform linux/amd64 -t butuz-documents:local -f $docRecipe .
$testRecipe = 'sandbox/Dockerfile'
docker build --platform linux/amd64 -t butuz-sandbox:local -f $testRecipe .
```

Точка в конце каждой строки обязательна: она указывает текущую папку исходников. Команда может занимать заметное время. Если процесс закончился ошибкой, прочитайте её; один успешный образ не заменяет второй.

4. Проверьте платформу каждого образа:

```powershell
docker image inspect butuz-documents:local --format '{{.Os}}/{{.Architecture}}'
docker image inspect butuz-sandbox:local --format '{{.Os}}/{{.Architecture}}'
```

Обе команды должны вывести linux/amd64. Образ linux/arm64 с Mac Apple Silicon не подходит для нашего Windows x64 комплекта.

5. Сохраните образы в переносимые файлы:

```powershell
docker save -o 'C:\Build\butuz-documents.tar' butuz-documents:local
docker save -o 'C:\Build\butuz-sandbox.tar' butuz-sandbox:local
```

6. Откройте C:\Build и убедитесь, что оба tar существуют и имеют ненулевой размер. Это не обычные текстовые документы, открывать и редактировать их не надо.

Документный образ связан с кодом профиля оформления. Если исходники форматирования изменились после создания tar, надо подготовить соответствующий новый образ; перенос старого tar к новой версии может быть отклонён проверкой приложения. Образы для тестов и документов не взаимозаменяемы.

## 15 Запустите сборку полной папки

1. Откройте обычный PowerShell. Добавьте C:\Build\uv в PATH текущего окна:

```powershell
$env:Path = 'C:\Build\uv;' + $env:Path
```

2. Сначала прочитайте Tools\Build-Windows.ps1 из полученного комплекта. Если Windows блокирует доверенный сценарий политикой запуска, согласуйте разрешение с администратором. Для разрешённого сценария можно установить RemoteSigned только для текущего процесса:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Этот выбор действует до закрытия окна. Если файл помечен как загруженный из интернета и всё ещё блокируется, после проверки происхождения откройте его «Свойства» и используйте «Разблокировать», если такой пункт есть. Корпоративная политика может запрещать это; тогда вопрос решает администратор. Не отключайте защиту Windows целиком.

3. Убедитесь, что C:\Build\BUTUZIK-AI-Windows-x64 **ещё не существует**. Сценарий специально не собирает поверх существующей папки, чтобы не затереть пользовательские данные. Для повторной попытки задайте новое имя результата.
4. Вставьте в это же окно целиком следующий блок. Скобки @{ и } должны остаться, а строки параметров не требуют символов продолжения:

```powershell
$settings = @{
    PythonRuntime = 'C:\Build\cpython312'
    FletRuntime = 'C:\Build\flet'
    FletVersion = '0.28.3'
    OllamaRuntime = 'C:\Build\ollama'
    HuggingFaceHub = 'C:\Build\hf-hub'
    OllamaModels = 'C:\Build\ollama-models'
    StandardsLibrary = 'C:\Build\standards-v1'
    DocumentImageTar = 'C:\Build\butuz-documents.tar'
    SandboxImageTar = 'C:\Build\butuz-sandbox.tar'
    Output = 'C:\Build\BUTUZIK-AI-Windows-x64'
}
& 'C:\Build\kit\Tools\Build-Windows.ps1' @settings
```

5. Дождитесь окончания. Сценарий копирует полный Python в новую папку, устанавливает Windows-библиотеки по uv.lock, добавляет интерфейс, сервер, модели, архив ГОСТ, tar образы и компилирует EXE. На этой стадии с интернетом скачивание библиотек нормально; обычный пользователь не должен повторять его при запуске.
6. Успешное завершение отмечается текстом Assembly complete. Только после этого переходите к проверкам. Возврат приглашения после красной ошибки не означает успешную сборку. Неполную папку не передавайте пользователю.

Не исправляйте ошибку отсутствующего пакета удалением проверок хешей или заменой lock-файла произвольными версиями. Сохраните сообщение и проверьте подходящую платформу, Python и полноту ресурсов.

### Если сборка тоже должна идти без интернета

Основной маршрут инструкции — собрать папку на ПК с сетью, а использовать её без сети. Это проще для первого развёртывания. Для сборки уже в закрытой сети дополнительно нужен заранее подготовленный wheelhouse: папка всех Windows x64 пакетов для CPython 3.12 с точными версиями и хешами из uv.lock.

Такую папку готовит ответственный за зависимости на совместимом Windows ПК. Кеш macOS, .venv разработчика или несколько вручную выбранных whl не подходят. После её получения положите wheels в C:\Build и перед строкой вызова сборщика добавьте:

```powershell
$settings.Wheelhouse = 'C:\Build\wheels'
```

Только после этого вызывайте Build-Windows.ps1 с @settings. В этом режиме экспорт требований не скачивает Python, установка использует только wheelhouse. Если пакета нет, сборка прекращается; сначала дополните набор на подготовительном ПК с сетью. Этот вариант не заменяет подготовку моделей, tar образов, WSL и установщиков.

Set-Location 'C:\Build\BUTUZIK-AI-Windows-x64'

## 17 Что копировать на флешку

Перед переносом закройте приложение и остановите его окно Ollama сочетанием Ctrl+C, дождитесь окончания процессов. Если в комплекте уже появилась нужная история, резервное копирование выполняйте по разделу 22.

1. В Проводнике откройте C:\Build. Выберите **всю папку BUTUZIK-AI-Windows-x64**, а не kit и не один EXE. Скопируйте её на флешку. Можно перенести ZIP всей готовой папки, если согласованный архиватор корректно обрабатывает её размер.
2. Проверьте ёмкость носителя. Большие модели и tar файлы могут превышать 4 ГБ на один файл. Для таких файлов нужен носитель с поддерживающей их файловой системой, например exFAT или NTFS. При форматировании флешки её содержимое стирается: сначала сохраните нужные данные, а саму процедуру согласуйте с владельцем носителя.
3. Отдельно положите папку Installers: согласованные установщики Docker, WSL x64, необходимых системных библиотек и драйверов для целевого ПК. Если там всё уже установлено и проверено, переустанавливать это каждый раз не надо.
4. Положите эту инструкцию рядом с готовой папкой, чтобы её можно было открыть ещё до запуска программы. Не включайте личные токены, всю папку профиля или несогласованные пользовательские документы.
5. Дождитесь окончания копирования и используйте «Безопасное извлечение» Windows. Не вытаскивайте накопитель во время копирования больших файлов.

После переноса целостность проверяется через Check-Offline.ps1. Для дополнительной сверки ZIP можно сравнить значение SHA256 на исходном и целевом ПК командой ниже, заменив путь реальным именем архива:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'E:\BUTUZIK-AI-Windows-x64.zip'
```

Буква E приведена как пример: ваша флешка может иметь другую букву. Отсутствие ZIP нормально, если передаётся распакованная папка. Установка Docker хранит свои данные вне переносимой папки, поэтому tar образы из Images нужны на новом ПК даже после успешного запуска на подготовительном.

## 18 Первый запуск на другом компьютере без интернета

1. Проверьте требования раздела 3. Администратор должен заранее установить подходящие WSL, Docker Desktop, драйверы и нужные системные библиотеки. В закрытой сети используются подготовленные установщики; команды pull, pip install и обычная интернет загрузка здесь не нужны.
2. Скопируйте всю готовую папку с флешки на локальный диск с правом записи. Для примера дальше используется C:\BUTUZIK-AI. Если туда нет доступа, выберите доступную папку пользователя и замените путь в командах. Не запускайте рабочую копию из архива, с флешки или из Program Files.
3. Откройте C:\BUTUZIK-AI и проверьте, что EXE лежит непосредственно в ней, рядом с App, Runtime, Flet, Ollama, Models, Images и Tools. Ошибка вложенности даёт неработающий запуск.
4. Запустите Docker Desktop из «Пуска». Дождитесь движка в режиме Linux containers. Откройте PowerShell и перейдите в папку программы:

```powershell
Set-Location 'C:\BUTUZIK-AI'
```

5. Проверяйте именно локальный Linux движок, которым пользуется приложение. В этом же окне выполните:

```powershell
$pipe = 'npipe:////./pipe/dockerDesktopLinuxEngine'
docker --host $pipe info --format '{{.OSType}}'
```

Ожидается linux. Если этот адрес отсутствует, проверьте второй поддерживаемый локальный адрес:

```powershell
$pipe = 'npipe:////./pipe/docker_engine'
docker --host $pipe info --format '{{.OSType}}'
```

Продолжайте только с адресом, который вывел linux. Если ни один не работает, устраните запуск Docker вместе с администратором. Не подменяйте его удалённым сервером.

6. Загрузите оба образа из локальных файлов. Переменная $pipe должна остаться заданной в том же окне:

```powershell
docker --host $pipe load -i '.\Images\butuz-documents.tar'
docker --host $pipe load -i '.\Images\butuz-sandbox.tar'
```

Дождитесь сообщения об успешной загрузке каждого. Это импорт с диска, не скачивание. Затем подтвердите архитектуру:

```powershell
$format = '{{.Os}}/{{.Architecture}}'
docker --host $pipe image inspect butuz-documents:local --format $format
docker --host $pipe image inspect butuz-sandbox:local --format $format
```

Оба результата должны быть linux/amd64. Импорт делают один раз для этой версии образов в этой установке Docker. При следующем обычном запуске команды load повторять не надо.

7. В Проводнике откройте Tools и запустите Start-Ollama.cmd. Окно сервера оставьте открытым. В PowerShell из корня программы проверьте модели:

```powershell
.\Ollama\ollama.exe list
```

Если в окружении компьютера настроен другой OLLAMA_HOST, сначала задайте в этом окне $env:OLLAMA_HOST = '127.0.0.1:11434'. В списке нужны модели из App\.env. Сервер из Start-Ollama использует Models\ollama данной папки.

8. Запустите проверку готовности:

```powershell
.\Tools\Check-Offline.ps1
```

При разрешённом запуске сценариев и полном комплекте ожидается Readiness checks passed. Ошибку нужно устранить до передачи пользователю, а не закрыть окно и считать проверку успешной.

9. Дважды щёлкните BUTUZIK.AI.exe и выполните все сценарии раздела 24 без интернета. Сохраните результат проверки. После успешной приёмки обычный пользователь может переходить к ежедневному маршруту.

## 20 Первые действия в приложении

### Обычный разговор

Создайте чат и отправьте «Привет, как тебя зовут». Ожидается имя BUTUZIK.AI. Для общего вопроса оставьте режим агента выключенным. Если нужен длинный ответ, прямо укажите желаемую подробность и задачу. Обычный ответ модели сам по себе не означает, что она использовала ваши документы.

### Поиск по документу

Подготовьте небольшой несекретный TXT: «Контрольный код проекта — ЛИСТ 427». Прикрепите его кнопкой файла и дождитесь обработки. Спросите: «Какой контрольный код указан в прикреплённом документе? Укажи источник». Проверьте правильный код и источник. Прикрепление относится к текущему чату; общая база настраивается отдельно.

В настройках можно выбрать согласованную папку общей базы и запустить её обработку. Сканированный PDF может не дать пригодного текста без отдельного распознавания. Для важных ответов сверяйте цифры и условия с исходником, а не только наличие названия файла в источниках.

Включите «Режим агента» и отправьте «Создай файл demo.txt с текстом Проверка запуска». В окне подтверждения проверьте имя, путь и будущее содержимое, затем разрешите запись. Откройте «Файлы чата», найдите demo.txt и прочитайте его. Одно сообщение «создал» без реально доступного файла проверкой не считается.

Для второго файла отклоните запись. Он не должен появиться. Чтобы сохранить готовый результат в удобную папку, используйте «Сохранить как» или открытие расположения из «Файлов чата». Вложения хранятся отдельно от результатов.

### Проверка Python проекта

Создайте на рабочем столе тестовую папку DemoProject. С включёнными расширениями через Блокнот сохраните в ней два файла; в диалоге «Сохранить как» выберите «Все файлы», чтобы не добавился .txt.

Файл calc.py должен содержать:

```python
def add(a, b):
    return a - b
```

Файл test_calc.py должен содержать:

```python
from calc import add

def test_add():
    assert add(2, 3) == 5
```

В новом чате включите агента, нажмите «Открыть проект», укажите папку DemoProject и подтвердите импорт. Отправьте «Найди ошибку в проекте, исправь её и запусти все тесты после изменения. Тестовый файл не меняй». Просмотрите предложенную правку и разрешите её, если она соответствует задаче.

Ожидаемый результат — исправленная копия в «Файлах чата», сохранённый test_calc.py и реальный успешный pytest после изменения. В calc.py должно стать return a + b. Исходная папка на рабочем столе остаётся входным оригиналом. Если агент остановился, выбрал не тот путь или тесты не прошли, запишите фактическую ошибку: это незавершённая проверка, а не доказательство успеха.

Проект импортируется с фильтрацией зависимостей, кешей, скрытых файлов, известных секретных имён, бинарных файлов и ссылок. Это не полная проверка всех секретов и не поддержка произвольного размера проекта. Текущие пределы импорта — до 1500 файлов, до 16 МБ суммарно и до 1 МБ на файл. Результаты тестов относятся к реально выполненным целям и снимкам файлов.

В контейнере тестов подготовлены Python, NumPy и pytest. Дополнительные библиотеки произвольного проекта туда не устанавливаются автоматически. Файлы, созданные только запущенной программой внутри временного контейнера, после его удаления не сохраняются в «Файлах чата»; постоянные результаты создаются файловыми инструментами агента.

### Картинка и оформление Word

Для картинки прикрепите простое несекретное изображение и спросите, что на нём. Переключать выбранную текстовую модель на vision вручную не требуется. Ошибки распознавания мелких надписей нужно проверять по оригиналу.

Текущий профиль частичный: таблицы, рисунки, реквизиты и техническое содержание требуют просмотра человеком. Программа не выдаёт сертификат соответствия всем ГОСТ. Для изображений используется VISION_MODEL_NAME; EMBEDDER_DEVICE в этой сборке — cpu. Затем сохраните файл без добавления .txt и повторите проверку готовности.

## 22 Как сохранить данные и обновить программу

1. Отмените активные запросы и ожидающие подтверждения. Закройте все экземпляры приложения и дождитесь окончания его Python процесса. При необходимости попросите администратора проверить это в Диспетчере задач.
2. Скопируйте целиком App\data, App\agent_workspace, App\config.json, если он есть, и App\.env в отдельную папку с датой. Сохраните также внешние оригиналы документов и проектов: они могут лежать за пределами программы.
3. История использует SQLite WAL. Во время работы приложения нельзя считать копию одного chats.sqlite3 полной резервной копией: последние записи могут находиться в файлах WAL. Обычный безопасный путь — полностью закрыть приложение и копировать рабочий каталог. Не удаляйте вручную файлы -wal и -shm открытой базы.
4. Новую версию распаковывайте в другую папку. Не запускайте сборщик поверх текущей рабочей установки. Перенос совместимых рабочих данных выполняйте после резервной копии, с учётом инструкции конкретного обновления.
5. Откройте новую версию, проверьте старые чаты, один сохранённый файл, документы и пользовательские пути. Старую папку сохраняйте до проверки новой версии и резервной копии.

Не используйте очистку всех данных как универсальный способ исправления сбоя. Если надо сделать живой снимок истории без остановки, разработчик использует ChatStore.backup; обычное копирование только основного SQLite файла во время работы не заменяет этот механизм.

## 23 Что делать если не получилось

### Команда не найдена или путь даёт False

Откройте указанный путь в Проводнике и найдите настоящий EXE или сценарий. Частая причина — дополнительная папка после распаковки. Для uv снова добавьте C:\Build\uv в PATH текущего PowerShell. После установки Docker откройте новое окно. Не скачивайте одноимённые программы со случайных сайтов.

### Сборка пишет Output already exists

Это защита от перезаписи. Найдите строку Output в блоке раздела 15 и задайте новое свободное имя, например C:\Build\BUTUZIK-AI-Windows-x64-2. Не удаляйте существующую папку, пока не проверили, нет ли в ней пользовательских данных. Следующие команды выполняйте уже из фактической новой папки.

### Заблокирован запуск PowerShell сценария

Проверьте происхождение файлов и используйте согласованную процедуру раздела 15. Ограничение организации может требовать действий администратора. Не заменяйте проверку безопасности постоянным отключением всех политик и антивируса.

### Docker показывает только Client или не находит pipe

Запустите Docker Desktop и дождитесь Linux движка. Проверьте WSL, виртуализацию и режим контейнеров. Повторите проверку двух локальных адресов из раздела 18. Если подготовка идёт в виртуальной машине, может требоваться вложенная виртуализация; её настраивает администратор. Другой удалённый Docker не является заменой этой локальной установки.

### Порт 11434 занят

Возможно, уже работает Ollama из трея или подготовительное окно А. Выясните, чья это служба и какие модели она использует. Для нашей переносимой установки нужен сервер с Models\ollama данной папки. Остановите только согласованную лишнюю копию и снова откройте Start-Ollama.cmd. Порт в .env без согласованного изменения архитектуры не меняйте.

### Модели нет в списке или ready равно false

Проверьте имена в App\.env и вывод Ollama list. Проверьте наличие manifests и blobs в Models\ollama. На закрытом ПК модель не появится сама: вернитесь к стадии подготовки или попросите полный комплект. Если ошибка embeddings, проверьте Models\huggingface\hub и правильную структуру кеша. Если нет vision, вопросы по картинкам не прошли приёмку.

### Ошибка DLL или Native DLL import failed

Сверьте x64, полный Windows Python и библиотеки из этой сборки. Используйте согласованный официальный Visual C++ Redistributable и подходящий драйвер. Не скачивайте отдельную DLL со стороннего сайта. Сохраните полное имя ошибки для администратора; случайная замена файла может нарушить другие библиотеки.

### Окно программы не появилось или быстро исчезло

Откройте Logs\launcher.log в корне программы. Проверьте, что Runtime\python.exe и App\windows_entry.py существуют, Flet полный, версии совпадают и папка доступна для записи. Не запускайте отдельный launcher из Downloads без всех соседних каталогов.

### Проверка хешей сообщает об изменении

Сравните с исходной проверенной папкой: копирование могло оборваться, антивирус мог переместить файл, либо часть программы была заменена. Восстановите корректную согласованную версию и повторите проверку. Не редактируйте bundle-manifest.json ради зелёного результата. Изменение рабочих чатов, обычных настроек и журналов само по себе не должно требовать переписывания хешей программы.

### Не хватает памяти или ответ очень медленный

Закройте ненужные программы и другие задачи модели. Проверьте RAM, место под Docker и длину контекста. Меньшая модель может помочь, но её надо подготовить и проверить отдельно. Не считайте зависание доказанным только потому, что первый ответ ещё не появился; следите за состоянием приложения и журналом.

### Агент сказал что сохранил но файла нет

Откройте «Файлы чата» именно текущего чата, проверьте results и факт разрешения записи. Вложения attached не являются готовыми результатами. Отказ, отмена, ошибка инструмента или завершение приложения могут предотвратить запись. Один текстовый ответ без сохранённого файла не принимайте как выполненную задачу; сохраните журнал и формулировку запроса.

### pytest не запускается или падает

Проверьте наличие butuz-sandbox:local для Linux amd64, точный проект и фактический вывод. Проект может требовать библиотеки, которых в образе нет. Отдельная проверка синтаксиса не является запуском тестов. Не включайте выполнение на основной Windows в качестве обхода изоляции; дополнительный образ готовят отдельным согласованным этапом.

### Оформление Word не сработало

Проверьте butuz-documents:local, соответствие коду этой поставки, формат DOC или DOCX и замечания подготовки. Неподдерживаемые объекты могут требовать ручной работы. Если проверка картинки или рамки неоднозначна, это не повод менять исходные технические данные. Оригинал сохраняйте отдельно.

### На флешку не копируется большой файл

Сравните свободное место и файловую систему носителя. FAT32 ограничивает размер отдельного файла; используйте подходящий заранее подготовленный носитель. Не форматируйте флешку с нужными файлами без резервной копии.

Если своими силами ошибка не решилась, сообщите ответственному: на каком шаге она возникла, точный текст, версию Windows, путь установки, RAM и GPU, есть ли интернет и что показывает Check-Offline. Приложите нужный фрагмент журнала без личных документов, паролей и токенов.

## 24 Когда можно отдавать комплект пользователю

Заполните эту таблицу по реальному запуску на целевом Windows x64 без интернета. Само наличие EXE, успешная компиляция и хеши файлов не заменяют эти проверки. Для заполнения сохраните отдельную копию инструкции вне папки программы. В графе результата поставьте «пройдено», «ошибка» или «не проверено», а рядом запишите фактическое наблюдение.

| Проверка | Что должно получиться | Результат и примечание |
|---|---|---|
| Готовность | Check-Offline завершается успешно | Заполнить |
| CHAT | Получен ответ на простой вопрос | Заполнить |
| SEARCH | Найден контрольный факт и правильный источник | Заполнить |
| Создание файла | demo.txt виден и открывается в «Файлах чата» | Заполнить |
| Отказ записи | Отклонённый файл не появляется | Заполнить |
| Проект | Правка есть в копии, оригинал сохранён | Заполнить |
| Тесты после правки | Реальный успешный pytest после сохранения | Заполнить |
| Картинка | Локальный анализ без переключения GUI модели | Заполнить |
| ГОСТ | DOCX подготовлен, страницы просмотрены, копия сохранена | Заполнить |
| Перезапуск | Старый чат и результат видны сразу | Заполнить |
| Остановка | Отмена ответа и следующий запрос работают | Заполнить |
| Путь с пробелами | Запуск и сохранение из согласованной папки работают | Заполнить |
| Офлайн и изоляция | Нет докачек, код идёт только в локальном контейнере | Заполнить |

В акте передачи дополнительно запишите: дату, ответственного, версию Windows, объём RAM, GPU и драйвер, версии Docker, WSL, Python, Flet и Ollama, имена моделей, версию исходников, хеш переданного архива и путь установки. Непройденные функции перечислите явно.

Состояние подготовки на 20 ноября 2026 года: на macOS прошли 474 теста; ранее выполнены проверка типов 53 модулей, диагностика моделей и баз, ещё 28 проверок с настоящими локальными контейнерами. На Windows Server x64 проверены PowerShell, компиляция launcher, пять тестов переносимого запуска и импорт основных Windows библиотек. Подготовлены два образа Linux amd64. В полном комплекте с именем OFFLINE уже находятся Python, Flet, Ollama, выбранные модели, библиотека ГОСТ, образы и установщики; скачивание и сборку исходного архива повторять не нужно. **Полная офлайн GUI приёмка на пользовательской Windows 10 или 11 ещё не выполнена.** Наличие файлов не подтверждает прохождение всех сценариев этой таблицы.

Для ежедневной работы после успешной приёмки достаточно раздела 19. Для подробностей всех возможностей сохранено отдельное руководство App\docs\user-guide-ru.md. Официальные источники приведены ссылками рядом с соответствующими действиями; перед подготовкой новой версии повторно проверьте требования поставщиков.
