# Подготовка полного офлайн комплекта

Это отдельный этап явной подготовки с интернетом. Во время обычной работы
приложение продолжает использовать только локальную Ollama и готовые образы.

Workflow `offline-components.yml` подготавливает полный CPython 3.12 x64,
замороженные зависимости из uv.lock и launcher на Windows. Он проверяет импорт
torch, Chroma, CTranslate2, PortAudio и lxml на Windows. Второй job собирает и
экспортирует два Linux amd64 образа. В GitHub не передаются модели, архивы
стандартов, чаты, документы пользователя или рабочие индексы.

`packaging/windows/assemble_offline.py` локально объединяет эти артефакты,
официальные Windows ZIP Flet/Ollama, установщики и существующие данные.
Он проверяет хеши артефактов и опубликованные контрольные суммы, точную
версию зависимостей/исходников образов, архитектуру образов и Windows PE.
Для Flet и Microsoft Redistributable, где в использованном источнике нет
отдельной опубликованной суммы, сохраняются URL и вычисленный SHA-256;
это не объявляется независимой проверкой подписи издателя.

Копируются только manifests/blobs qwen2.5:14b и qwen2.5vl:7b, четыре явных
репозитория моделей поиска/голоса и source.pdf/catalog.json 12 точных
зарегистрированных редакций. Неизвестные модели, токены, личная история,
Chroma и обычные документы не попадают в поставку. Исходные данные сохраняются.
Все стандартные архивы проверяются standards_library.load перед копированием.

Сборщик не запускает Windows EXE на macOS, не принимает лицензии установщиков
и не выполняет установку компонентов в пользовательской Windows. Полная GUI
приёмка остаётся отдельным обязательным шагом. Комплект со стандартами
предназначен для согласованной передачи и не публикуется в Git.

Установщики включены для однократной подготовки Windows. Прежде чем запускать
их в организации, администратор проверяет совместимость, издателя и применимые
условия. Не выдавайте наличие всех файлов за прохождение офлайн GUI сценариев.

Сначала создаётся новый каталог, затем bundle-manifest.json. Ошибка не создаёт
готовый ZIP. ZIP64 хранит большие файлы моделей без повторного сжатия; остальные
компоненты сжимаются. Рядом записывается SHA-256 архива. Проверяйте архив после
копирования и используйте носитель, поддерживающий файлы больше 4 ГБ.
