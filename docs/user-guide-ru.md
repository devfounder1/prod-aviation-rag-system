# Руководство пользователя BUTUZIK AI

Локальный помощник для общения, поиска по документам, работы с файлами и Python-проектами. Подробное руководство пользователя и администратора для Windows x64. Состояние поставки: 20 ноября 2026 года.

## 1 Как читать руководство

Обычному пользователю: прочитайте разделы 2–17, а при проблеме найдите её в разделе 18. Администратору, который переносит программу на компьютер без интернета: дополнительно выполните разделы 19–25. Термин «корневая папка» означает папку распакованного комплекта, где после сборки находится BUTUZIK.AI.exe.

Важное различие: комплект исходников с ASSEMBLY_REQUIRED.txt ещё нужно собрать на Windows. В нём нет Windows Python, готового EXE, весов моделей и образов Docker. Полный собранный комплект содержит Runtime, Flet, Ollama, Models, Images и EXE. Ни наличие архива, ни успешная проверка хешей сами по себе не доказывают, что GUI проверен на Windows. Перед передачей пользователям администратор выполняет приёмку из раздела 24.

BUTUZIK.AI — имя приложения и помощника. Создатель приложения — Demashov Michail Sergeevich. Выбранная модель Qwen или другая установленная модель Ollama является отдельным компонентом.

## 2 Что умеет программа

CHAT отвечает на общие вопросы, объясняет понятия, помогает составлять тексты. SEARCH ищет информацию в загруженных документах и формирует ответ с источниками. AGENT использует инструменты: читает материалы, создаёт и исправляет файлы, исследует импортированный проект и запускает доступные Python-тесты в локальном контейнере. Явно включённый «Режим агента» имеет приоритет над автоматическим выбором режима.

Изображение анализируется отдельной локальной vision-моделью, после чего выбранная текстовая модель отвечает пользователю. Самостоятельно переключать модель в интерфейсе ради картинки не требуется. Наличие изображения не делает ответ проверенным измерением: мелкие подписи, геометрия, числа и схемы требуют проверки.

Кнопка «Оформить по ГОСТ» работает с существующим DOC/DOCX. Она подготавливает отдельный редактируемый DOCX и показывает страницы и замечания перед сохранением. PDF как исходник для автоматического восстановления структуры Word пока не поддерживается этим сценарием.

Модель может ошибаться, не знать данных, не найти нужный фрагмент или исчерпать контекст. Успешное сохранение файла не означает правильность его содержания. Прохождение выбранных тестов не означает правильность всего проекта.

## 3 Компьютер и свободное место

Целевая платформа комплекта — Windows x64. Windows ARM64 и 32-разрядные системы не входят в эту сборку. Для полного сценария с контейнерами предпочтительна поддерживаемая Windows 11 с доступной аппаратной виртуализацией. Возможность установки на конкретную Windows 10 определяется актуальными требованиями выбранных версий Docker Desktop и Ollama, а не только надписью x64.

Ориентиры ниже — оценки для планирования, а не гарантии скорости. Потребление зависит от квантования модели, длины контекста, размера файлов, GPU и одновременно работающих программ.

| Конфигурация | Практический ориентир |
|---|---|
| 16 ГБ RAM | Начать с небольшой текстовой модели около 7B; тяжёлые модели, vision и контейнеры могут не поместиться одновременно |
| 32 ГБ RAM | Более разумная отправная точка для Qwen 14B и документов; длинный контекст и параллельные задачи всё ещё ограничены |
| 64 ГБ RAM | Больше запаса под 14B, расширенный контекст, индексацию и контейнеры |
| Только CPU | Возможен запуск совместимых моделей, но генерация и индексация могут быть медленными |
| NVIDIA GPU | Ускорение зависит от драйвера, VRAM, квантования и поддержки Ollama; наличие GPU не гарантирует размещение всех моделей |

Планируйте десятки гигабайт под Runtime, Ollama, веса текстовой и vision-модели, эмбеддинги и образы. Для полного комплекта с запасом на распаковку, Docker и результаты разумно заранее выделить 80–150 ГБ, затем уточнить объём по фактической поставке. Это не минимальный размер программы. На флешке FAT32 отдельные файлы больше 4 ГБ не помещаются: используйте подходящий носитель, согласованный с администратором, например exFAT/NTFS.

Администратор устанавливает необходимые Windows-компоненты, драйверы и системные библиотеки заранее. Работа без сети не означает отсутствие предварительной установки WSL, Docker Desktop или драйвера GPU.

## 4 Куда распаковать и что запускать

1. Создайте локальную папку, например C:\Users\User\BUTUZIK-AI. Пользователь должен иметь право записи во все её рабочие подпапки.
2. Распакуйте туда весь собранный комплект. Не запускайте программу внутри ZIP.
3. Не помещайте рабочую копию в Program Files, папку Windows, сетевое хранилище или синхронизируемую папку OneDrive. Иначе возможны отказы записи или конфликты баз.
4. Убедитесь, что рядом с EXE остались папки Runtime, Flet, Ollama, Models, App, Images и Tools. Один EXE без них недостаточен.
5. Для первого запуска выполните действия следующего раздела. Не открывайте отдельные PY-файлы двойным щелчком: Windows может выбрать другой установленный Python.

Если получен исходный комплект без EXE, обычный пользователь передаёт его администратору. Нельзя получить готовую программу простым переименованием файла или копированием Python с macOS.

## 5 Первый запуск собранного комплекта

1. Если нужны тесты кода или оформление по ГОСТ, запустите Docker Desktop. Дождитесь готовности Linux engine. Загружать образы из интернета при работе программа не будет.
2. Если Ollama уже работает в системном трее, выясните с администратором, какая копия использует порт 11434 и где её модели. Две службы на одном порту одновременно не запустятся.
3. Для переносимого Ollama откройте Tools\Start-Ollama.cmd. Окно сервера оставьте открытым. Этот сценарий задаёт Models\ollama как хранилище весов и использует адрес 127.0.0.1:11434.
4. При первой установке администратор запускает Tools\Check-Offline.ps1 в PowerShell. Если файл заблокирован политикой организации, обращайтесь к администратору; не меняйте системную политику безопасности самостоятельно.
5. Дважды щёлкните BUTUZIK.AI.exe. Первое открытие может занять время из-за импорта тяжёлых библиотек.
6. При запросе папки документов выберите существующую папку с согласованным набором исходников. В интерфейсе ещё встречается историческое имя «PRL-27» — это название раздела технической базы, а не требование к имени вашей папки.
7. Отправьте «Привет». Дождитесь ответа и возврата индикатора в готовое состояние.
8. Закройте приложение крестиком, затем откройте снова. Чаты должны появиться сразу в боковой панели.

Не нажимайте EXE много раз подряд во время первого старта: это может запустить несколько экземпляров. Ожидаемое время проверяется на целевом компьютере; универсального норматива нет.

## 6 Ориентация в окне

В боковой панели находятся сохранённые чаты и создание нового чата. Центральная часть показывает переписку. Внизу находятся поле ввода, отправка, прикрепление файла, голосовой ввод, «Режим агента», «Файлы чата», «Оформить по ГОСТ» и «Открыть проект». В настройках выбираются доступная модель и пути баз знаний.

Индикаторы «думаю», «ищу», работа с файлами и ожидание подтверждения показывают фазу обработки. Пока открыт запрос подтверждения, агент ждёт вашего решения. Эти состояния не являются частью ответа и не должны сохраняться как сообщение модели.

Если нужной кнопки не видно, увеличьте окно. Для первого знакомства используйте текстовый ввод; голос не обязателен. Если загружен старый интерфейс, закройте все экземпляры и убедитесь, что запускаете EXE именно из новой папки.

## 7 CHAT и управление чатами

Создайте новый чат для новой темы, введите вопрос и нажмите отправку. Например: «Объясни на простом примере разницу между напряжением и током». Для более точного результата укажите цель, аудиторию и желаемый объём: «Объясни подробно, с примерами и ограничениями».

Для продолжения темы используйте тот же чат. Старые чаты и сообщения хранятся локально. После перезапуска они должны отображаться без нажатия «Новый чат». Если история пропала, сначала проверьте, не открыта ли другая копия программы: разные папки App имеют разные базы истории.

Запросы о содержимом ваших документов требуют загрузки/индексации источников. Обычный ответ из общих знаний модели не подтверждает, что она открыла ваш файл. Для важных данных просите ссылки на конкретные источники и проверяйте их.

Для удаления чата внимательно читайте окно подтверждения. Не используйте «Полная очистка всех данных» как способ исправить мелкую ошибку: это отдельное удаляющее действие. Перед очисткой сделайте резервную копию.

## 8 Подготовка документов для SEARCH

Есть два повседневных способа дать помощнику материалы: прикрепить файл в текущий чат либо добавить согласованную папку в общую базу через настройки. Копии вложений изолированы по чату. Материалы, загруженные с областью global, доступны всем чатам этой установки.

В настройках исторический раздел базы PRL-27 содержит кнопку «Перестроить индекс». Он формирует основную техническую коллекцию. Раздел «Универсальная база знаний» содержит «Синхронизировать базу знаний» и добавляет общие материалы. Не запускайте перестроение наугад при работающих запросах. Перед изменением большого индекса сделайте резервную копию и сохраните исходники.

Порядок загрузки папки: подготовьте отдельный каталог; поместите туда только разрешённые рабочие документы; выберите каталог в настройках; запустите соответствующую обработку; дождитесь сообщения о завершении. Объём и качество извлечения зависят от формата. PDF со сканами или сложными таблицами может не дать достаточного текста; OCR не включается автоматически при каждом запросе.

Индексация не превращает текст PDF в набор проверенных правил ГОСТ. База общих документов и проверяемая библиотека редакций стандартов — разные механизмы, хотя данные могут относиться к одному предмету.

## 9 Поиск с источниками

После загрузки спросите: «По загруженным документам подробно объясни назначение сигнала PPS. Укажи источники и условия применимости». Для конкретного оборудования укажите точное обозначение и имя документа: «Найди порядок проверки узла Д1ПК002 в прикреплённом ТУ».

Автоматический маршрутизатор выбирает CHAT или SEARCH. Если включён агент, документные вопросы также должны пользоваться общим поиском. Не существует отдельной второй базы только для агента.

Прочитайте ответ и список источников. Проверьте, что имя документа соответствует вопросу, что приведённые числа и условия найдены именно в нём, и что модель не смешала разные исполнения. Источник внизу ответа не равен независимому подтверждению каждой фразы.

Если ответ слишком краток: попросите «развёрнуто, по пунктам, со значениями, ограничениями и источниками». Если нужного фрагмента нет: уточните обозначение, проверьте загрузку документа и наличие текста. Повторение того же вопроса не исправит отсутствующий или нечитаемый источник.

## 10 Изображения и голос

Для картинки прикрепите PNG/JPEG или другой поддерживаемый интерфейсом файл и напишите, что нужно определить. Изображение сначала анализирует локальная vision-модель VISION_MODEL_NAME, по умолчанию qwen2.5vl:7b. Выбранная в чате модель остаётся прежней. Если vision-веса не подготовлены, анализ изображения завершится явной ошибкой; текстовый чат может продолжить работу.

Для схем и мелких надписей прикладывайте читаемое изображение. Не принимайте визуально угаданную цифру за измерение. При необходимости подтвердите её по оригиналу.

Голос использует микрофон и локальные Whisper base/small. Windows должна разрешать доступ настольных приложений к микрофону. При отсутствии моделей или микрофона используйте клавиатуру. В настройках можно отключить голосовую активацию «Бутуз». Ложное срабатывание wake-word возможно, особенно рядом с разговором или звуком компьютера.

Если на экране открыт запрос записи файла, голосовое «да» не заменяет кнопку подтверждения. Голосовой ввод не должен служить обходом окна согласования.

## 11 Создание файла агентом

1. Включите «Режим агента».
2. Укажите действие, имя, формат и содержимое. Пример: «Создай hello.txt с текстом Привет, мир и сохрани в Файлы чата».
3. Дождитесь окна, где видны путь и будущее содержимое.
4. Проверьте текст и имя. Нажмите «Разрешить запись» либо «Отмена».
5. Дождитесь завершения. Итог должен сообщать о действительно сохранённом файле, а не только показывать текст в сообщении.
6. Откройте «Файлы чата» и проверьте результат.

Каждая отдельная запись требует своего подтверждения. Отказ, отмена, истечение ожидания или устаревшая задача предотвращают ожидающую запись. Если модель только пообещала сохранить файл, а в списке его нет, сохранение нельзя считать выполненным.

Поддержка конкретных форматов зависит от доступных инструментов. Назвать файл report.docx недостаточно для создания корректного Word-документа: результат должен быть создан подходящим инструментом. В сценарии «Оформить по ГОСТ» DOCX формируется отдельным обработчиком.

## 12 Редактирование вложения и получение результата

Прикрепите файл и сформулируйте точечную задачу: «В конце этого Python-файла добавь вывод HELLO WORLD десять раз. Сохрани изменённую копию; остальной код сохрани». Агент читает файл и предлагает будущие байты. Проверьте окно перед записью.

Входная копия находится в attached, результат обычно публикуется в results. Исходный файл на вашем диске не должен изменяться при обычном редактировании вложения. Работа с оригиналом является отдельным действием с отдельным подтверждением.

В «Файлах чата» доступны «Показать в папке», «Открыть папку» и «Сохранить как…». Последняя команда делает явную копию в выбранное место. Не ищите файл по всему диску: сначала откройте этот список. Длинные списки разбиты на страницы.

Результат не появляется автоматически на рабочем столе или в папке Документы Windows. Скопируйте его через «Сохранить как…», если нужно отправить коллеге. Копии вложений и служебные реестры в обычном списке результатов скрыты.

## 13 Работа с папкой Python-проекта

Нажмите «Открыть проект». Во встроенном окне перейдите к нужной папке либо вставьте полный путь. Подтвердите «Импортировать проект». Дождитесь сообщения о числе файлов. Программа создаёт отдельный снимок с сохранением структуры каталогов и включает агента.

Исходная папка на диске остаётся прежней. Повторный импорт создаёт другой снимок; это не фоновая синхронизация. Для изменения ранее импортированного проекта продолжайте работу в том же чате и уточняйте, какой снимок нужен.

Лимиты: до 1500 текстовых файлов, 16 МБ суммарно, до 1 МБ на файл. Зависимости, типовые кеши/сборки, скрытые файлы, .env, известные имена секретов, двоичные файлы и ссылки исключаются. Это фиксированный фильтр, а не полная реализация .gitignore и не универсальный поиск всех секретов. Перед импортом проверьте папку сами.

Пример задачи: «Найди причину падения тестов, исправь исходный модуль и повторно запусти весь доступный pytest. Тесты не меняй. Перед правкой покажи изменения». Агент ищет по карте проекта, читает нужные диапазоны и использует реальные пути инструментов. Модель не получает весь проект одним огромным сообщением.

Первая подтверждённая правка публикует полную копию проекта в results/projects. Следующие чтения, изменения и тесты должны обращаться к актуальной копии. Для возврата результата откройте «Файлы чата» и скопируйте нужную папку; автоматического применения к исходному проекту нет.

Карта функций, классов и импортов строится для Python. Для других текстовых языков доступны пути и поиск текста, но это не обещание полноценной поддержки их сборок и тестов.

## 14 Запуск кода и тестов

Исполнение разрешено только в подготовленном локальном Linux-контейнере butuz-sandbox:local. Контейнер не имеет сети, работает не от root, получает фильтрованный снимок и ограниченные ресурсы. Записи внутри контейнера после завершения отбрасываются. Приложение не переходит на запуск Python на Windows-хосте, если Docker недоступен.

Образ содержит заранее установленный набор, в текущем рецепте Python, NumPy и pytest. Если проект требует другие пакеты, их должен заранее включить администратор в отдельной подготовке образа с последующей проверкой. Агент не выполняет pip install из интернета при работе.

Проверка синтаксиса Python до записи не выполняет код. Запуск pytest — отдельное действие. Читайте цель запуска, код завершения, stdout и stderr. Ноль означает успех конкретного выполненного запуска, а не доказательство полного покрытия проекта.

При просьбе «исправь и проверь» приложение отслеживает, были ли тесты запущены после последней правки. Старый зелёный запуск до изменения недостаточен. Если тесты упали, зависимость отсутствует или время закончилось, результат должен остаться явно неуспешным/незавершённым.

Исполнение идёт в Linux: код, зависящий от win32api, COM, Excel, реестра Windows или установленного на хосте ПО, может не работать в этой песочнице. Она не является Windows-VM и не подтверждает совместимость проекта с Windows.

## 15 Оформление документа по ГОСТ

1. Сохраните оригинал DOC/DOCX отдельно. Для первой проверки возьмите копию без макросов и цифровой подписи пакета.
2. Прикрепите документ к текущему чату и нажмите «Оформить по ГОСТ».
3. Выберите вид документа. Для технических условий явно выберите ТУ и представление документа, например макет для печати с рамками и штампами. Для нового запроса выбор подтверждается заново.
4. Нажмите «Подготовить документ» и дождитесь контейнерной обработки.
5. В окне согласования просмотрите вкладки «Страницы», «Текст», «Проверки» и «Покрытие ГОСТ». Кнопками «Назад»/«Далее» просмотрите каждую страницу.
6. Проверьте таблицы на границах страниц, подписи продолжений, интервалы 1,5 в основном тексте, единицы рядом с числами, рисунки, рамки, номера листов и оглавление.
7. Прочитайте предупреждения. Если результат неприемлем, нажмите «Отмена».
8. Если страницы и замечания проверены, отметьте «Я проверил страницы и замечания; сохранить этот проект DOCX» и нажмите «Сохранить DOCX».
9. Откройте результат через «Файлы чата». Для передачи в работу сделайте копию через «Сохранить как…».

Обработчик использует заранее подготовленный butuz-documents:local. При несовпадении версии обработчика и исходного кода выдаётся ошибка устаревшего образа; его пересобирает администратор. Установка Word/LibreOffice на Windows сама по себе не заменяет контейнер. Автоматического host-конвертера нет.

## 16 Что означает покрытие ГОСТ

В библиотеке зарегистрированы 12 конкретных предоставленных PDF-редакций. Оригинальные PDF и извлечённые страницы сохраняются. Полный текст архива не означает, что каждое правило реализовано или выбрано для вашего документа.

Исполняемый профиль использует выбранные операции Р 2.105/Р 2.104. Сохраняются технический текст, данные таблиц, рисунки и непрозрачные объекты. Для ГОСТ 2.114 есть отдельный перечень 148 контрольных позиций, который не выдаёт автоматического инженерного заключения. Смысловые требования, применимость, подписи и недоступные исходные документы остаются видимыми вопросами.

На этапе 20 ноября добавлены ограниченные проверки примечаний, повреждённых буквальных ссылок, повторения единиц в рядах, обычных формул в таблицах, нормативных ссылок и сокращений. Каждое замечание показывает точное место. Сокращённые фрагменты помечаются. Замечание не разрешает модели выдумать правильный номер ссылки, допуск, формулу или расшифровку.

Для нашего ТУ отдельно подготовлены новые редактируемые рамки и штампы форм 2/2а и пустой шаблон. Их замена выполнена по отдельному явному запросу в проверенной копии. Обычная кнопка оформления автоматически не подменяет старую графику этим шаблоном. Выбор нового бланка ещё не интегрирован в общий GUI-сценарий.

Наличие сертификата соответствия, полная семантическая проверка всех ГОСТов, автоматическое восстановление DOCX из произвольного PDF и перерисовка связей схем не входят в текущие возможности. Для окончательного документа проверяющий подтверждает замечания по КД, ТЗ, ОТУ и документации приборов.

| Симптом | Что проверить и сделать |

## 20 Резервное копирование и обновление

1. Завершите запросы, отмените ожидающие окна записи и закройте все экземпляры приложения.
2. Дождитесь остановки Python-процесса. По возможности закройте другие программы, использующие эту же базу.
3. Скопируйте целиком App/data, App/agent_workspace, App/config.json и App/.env в отдельную папку с датой. Если config.json ещё не создан, его отсутствие нормально.
4. Сохраните внешние исходные документы и папки проектов: они могут находиться за пределами комплекта.
5. Для обновления распакуйте новую версию в ДРУГУЮ папку, затем перенесите рабочие данные после проверки совместимости. Не запускайте сборщик поверх действующей рабочей папки.
6. Проверьте историю, один результат, документный поиск и настройки путей. Старую копию удаляйте только после приёмки новой и проверки резервной копии.

SQLite использует WAL. Нельзя копировать только chats.sqlite3 во время работы и считать это полной актуальной резервной копией: новые транзакции могут находиться в WAL. Для живого снимка разработчик использует ChatStore.backup; обычному пользователю проще полностью закрыть приложение и копировать рабочие каталоги. Не удаляйте вручную файлы -wal/-shm у открытой базы.

Пример живого снимка для администратора из корня собранного комплекта, после согласования пути назначения:

```powershell
Set-Location .\App
..\Runtime\python.exe -c "from pathlib import Path; from chat_store import ChatStore; s=ChatStore(Path('data/chats.sqlite3'),Path('chats_history.json')); s.backup(Path('data/backups/chats-manual.sqlite3'))"
```

Имя назначения должно быть новым: backup отказывается перезаписывать существующий файл. Это команда для истории, не полная резервная копия Chroma, результатов и исходников.

## 21 Администратору Что подготовить заранее

Подготовка выполняется на Windows x64 с интернетом либо с полным локальным набором пакетов. Рабочий ПК без интернета не должен пытаться скачать недостающую часть. Установка и сборка требуют прав и согласования по правилам организации.

Необходимы: исходный комплект App/Tools; uv для сборки; полноценный переносимый CPython 3.12 x64; Flet Windows той же версии, что locked flet-desktop; Ollama Windows amd64 со всеми нужными библиотеками; локальные веса; подготовленные tar-образы; архивы предоставленных редакций стандартов; C#-компилятор из .NET Framework для launcher EXE. На целевом ПК нужны совместимые системные библиотеки; при DLL-ошибках установить официальный x64 Visual C++ Redistributable из заранее проверенного установщика. Его наличие не гарантирует пригодность произвольной версии всех GPU-библиотек.

Полноценный Python можно подготовить средствами uv на сборочной Windows-машине. Не передавайте .venv с абсолютной ссылкой на Python разработчика, macOS/Linux-интерпретатор или Windows embeddable ZIP без настроенных зависимостей.

```powershell
uv python install 3.12
$PythonExe = uv python find --managed-python 3.12
$PythonRuntime = Split-Path $PythonExe -Parent
& $PythonExe -c "import sys,platform; print(sys.version, platform.machine(), sys.executable)"
```

Проверьте x64 и Python 3.12. Сценарий сборки копирует этот runtime в отдельную новую папку и устанавливает зависимости туда, а не в системный Python. Замороженные версии/хеши экспортируются из uv.lock. Сборка с доступом к сети может скачать Windows wheels; для полностью офлайн-сборки заранее подготовьте совместимый wheelhouse и передайте -Wheelhouse.

Flet: возьмите полный распакованный flet-windows.zip ровно соответствующего release, а не один exe. Нужны соседние DLL/data. Имя релиза и его источник/контрольную сумму зафиксируйте в акте сборки. Скрипт сравнивает указанный -FletVersion с версией Python-пакета; он не доказывает происхождение произвольного переданного flet.exe. Проверка GUI обязательна.

Ollama: можно использовать официальный standalone Windows amd64 ZIP, полностью распакованный. Включите требуемые GPU-библиотеки и согласованные лицензии компонентов. Совместимость с конкретным драйвером проверяется на целевом ПК. Существующие модели платформенно переносимы как данные, но исполняемые файлы и библиотеки должны быть Windows x64.

## 22 Подготовка моделей и стандартов

На подготовительной машине загрузите выбранные Ollama-модели ДО отключения сети. Это явная операция администратора, не действие программы во время ответа.

```powershell
ollama pull qwen2.5:14b
ollama pull qwen2.5vl:7b
ollama list
```

Если выбрана другая модель, измените App/.env после сборки и проверьте tool calling, поиск и vision отдельно. Не все модели поддерживают инструменты. Меньшая модель может работать быстрее, но это не гарантия сохранения качества сложного ремонта проекта.

Перед копированием хранилища остановите сервер Ollama. Переносите полные manifests и blobs из согласованного каталога моделей. Одного GGUF или одного manifest недостаточно для текущей схемы запуска. Start-Ollama.cmd использует именно Models/ollama; наличие весов в другом Windows-профиле не означает, что они доступны этой копии сервера.

Для проекта можно подготовить локальный профиль с увеличенным контекстом из App/ollama/Modelfile.agent, использующий уже имеющиеся веса:

```powershell
Set-Location .\App
ollama create butuz-qwen2.5:14b -f .\ollama\Modelfile.agent
```

Затем выберите точное имя профиля и проверьте память. AGENT_CONTEXT_CHARS в .env ограничивает приблизительный объём сообщений приложения; он не устанавливает реальное токеновое окно Ollama.

Для Hugging Face подготовьте полный локальный hub-кеш. Обязательная модель — intfloat/multilingual-e5-small. Для улучшенного ранжирования используется BAAI/bge-reranker-v2-m3; без него поиск может работать с предупреждением и другим качеством. Для голоса нужны Systran/faster-whisper-base и Systran/faster-whisper-small. На подготовительном ПК можно явно вызвать snapshot_download с заданным cache_dir:

```powershell
python -c "from huggingface_hub import snapshot_download; repos=['intfloat/multilingual-e5-small','BAAI/bge-reranker-v2-m3','Systran/faster-whisper-base','Systran/faster-whisper-small']; [snapshot_download(r,cache_dir=r'C:\Build\hf-hub') for r in repos]"
```

Эта команда нужна только при подготовке с интернетом; Python должен иметь huggingface_hub. В окружении подготовки не должны быть включены HF_HUB_OFFLINE/TRANSFORMERS_OFFLINE, иначе загрузка не состоится. В рабочем приложении эти флаги включены. Не переносите токен авторизации Hugging Face вместе с кешем. Сборщику передаётся папка hub, содержащая models--..., refs, snapshots и blobs. Он разыменовывает ссылки при копировании; проверьте итоговую целостность и размер.

Стандарты передаются отдельным параметром -StandardsLibrary: существующий архив v1 с исходными PDF и извлечёнными страницами. Не копируйте весь App/data разработчика: там находятся его история и другие личные данные. Используйте только согласованную библиотеку редакций и проверьте право её передачи. Реестр App/standards/library.json сам по себе исходные PDF не содержит. Не заменяйте PDF другой редакцией под прежним хешем.

## 23 Образы Docker и сборка папки с EXE

На подготовительной Windows-машине установите и запустите Docker Desktop с Linux containers и подготовленным WSL 2. Аппаратная виртуализация должна быть включена. Установщик Docker, WSL и необходимые обновления надо перенести/установить заранее; EXE приложения не включает WSL и не устанавливает системные компоненты.

Из папки App выполните явную подготовку Linux amd64 образов. Эти команды могут обращаться к сети и установщикам внутри Docker только на стадии подготовки:

```powershell
docker build --platform linux/amd64 -t butuz-documents:local -f document_runtime/Dockerfile .
docker build --platform linux/amd64 -t butuz-sandbox:local -f sandbox/Dockerfile .
docker image inspect butuz-documents:local --format '{{.Os}}/{{.Architecture}}'
docker image inspect butuz-sandbox:local --format '{{.Os}}/{{.Architecture}}'
docker save -o C:\Build\butuz-documents.tar butuz-documents:local
docker save -o C:\Build\butuz-sandbox.tar butuz-sandbox:local
```

Ожидается linux/amd64. Образ, экспортированный с Apple Silicon как linux/arm64, не считается подходящим для Windows x64. Документный образ должен соответствовать исходному коду именно этой поставки. Не пересобирайте старый рецепт поверх нового комплекта без проверки fingerprint.

На подготовительной Windows-машине запустите Tools/Build-Windows.ps1. Сначала откройте PowerShell, перейдите в корень исходного комплекта. Все пути ниже — пример структуры; замените их реальными путями к подготовленным ресурсам.

```powershell
.\Tools\Build-Windows.ps1 `
  -PythonRuntime 'C:\Build\cpython312' `
  -FletRuntime 'C:\Build\flet' `
  -FletVersion '0.28.3' `
  -OllamaRuntime 'C:\Build\ollama' `
  -HuggingFaceHub 'C:\Build\hf-hub' `
  -OllamaModels 'C:\Build\ollama-models' `
  -StandardsLibrary 'C:\Build\standards-v1' `
  -DocumentImageTar 'C:\Build\butuz-documents.tar' `
  -SandboxImageTar 'C:\Build\butuz-sandbox.tar' `
  -Output 'C:\Build\BUTUZIK-AI-Windows-x64'
```

Путь PythonRuntime должен быть корнем реального полного CPython, где лежит python.exe. Путь FletRuntime должен непосредственно содержать flet.exe и соседние ресурсы; если ZIP создал вложенную папку flet, передавайте её. Output обязан быть новым: сборщик не перезаписывает существующую рабочую папку.

Сборщик экспортирует зависимости из lock-файла, устанавливает их в скопированный Python, добавляет Flet и Ollama, модели и архив стандартов, копирует образы и компилирует BUTUZIK.AI.exe из Launcher.cs. EXE запускает App/windows_entry.py включённым Runtime/python.exe. Затем формируется bundle-manifest.json. Не переносите папку до успешного завершения команды; частично собранный каталог нужно считать неполным.

Для сборки без интернета добавьте -Wheelhouse 'C:\Build\wheels'. Wheelhouse должен содержать все Windows x64 wheels для CPython 3.12 с версиями и хешами из экспортированных требований. macOS wheels не подходят. При отсутствии пакета сборка должна завершиться ошибкой; не удаляйте --require-hashes ради обхода проблемы.

Сборщик не подтверждает правильность параметров установщика Docker, лицензирование, заполнение ГОСТ или качество модели. Не утверждайте «работает на Windows», пока не выполнена приёмка ниже. После сборки упакуйте всю готовую папку; архив может быть очень большим. Проверьте объём и файловую систему носителя.

## 24 Перенос без интернета и приёмка

1. Подготовьте на целевом ПК Windows x64, драйверы, согласованные системные библиотеки, WSL 2 и Docker Desktop. Проверьте их работу до запуска приложения.
2. Перенесите и полностью распакуйте готовую папку в локальный каталог с правом записи. Сравните хеш архива с передающей машиной, если он предоставлен.
3. Запустите Docker Desktop в режиме Linux containers. Для импортирования образов используйте заранее подготовленные tar:

```powershell
docker --host npipe:////./pipe/dockerDesktopLinuxEngine load -i .\Images\butuz-documents.tar
docker --host npipe:////./pipe/dockerDesktopLinuxEngine load -i .\Images\butuz-sandbox.tar
```

Если данная установка использует pipe docker_engine, администратор проверяет именно локальный Linux engine и заменяет адрес. Не применяйте удалённый DOCKER_HOST для обхода локальной изоляции. Приложение пробует только два фиксированных локальных Windows pipe.

4. Запустите Tools/Start-Ollama.cmd и проверьте список локальных моделей. Если работает другая Ollama-служба, сначала выясните её конфигурацию; не завершайте чужие процессы без согласования.
5. Запустите .\Tools\Check-Offline.ps1. Проверка читает хеши, настройки локальных моделей, native imports, Docker-образы и архив стандартов. При первой установке отсутствие ещё не созданной базы истории может быть предупреждением; потеря уже существующей базы — отдельная проблема.
6. Отключите интернет на целевой машине, сохранив работу localhost. Запустите EXE из Проводника и выполните все сценарии таблицы.

| Сценарий | Признак успешной приёмки |
|---|---|
| CHAT | Ответ на простой вопрос, возврат в готовое состояние |
| SEARCH | Загрузить синтетический документ с уникальным фактом, получить этот факт и источник |
| AGENT файл | Разрешить создание demo.txt, прочитать его из «Файлов чата», проверить точные байты |
| Отказ записи | Отменить другое создание; ожидаемый файл не появляется |
| Проект | Импортировать небольшой синтетический Python-проект, исправить ошибку, разрешить изменение |
| Тесты после правки | Получить действительный новый pytest-результат после сохранения, а не проверку синтаксиса |
| Изображение | Описать несекретную тестовую картинку без переключения текстовой модели |
| ГОСТ | Подготовить синтетический DOCX, просмотреть страницы/замечания, сохранить отдельную копию |
| Перезапуск | Чат и результат доступны сразу после закрытия/повторного запуска |
| Остановка | Прервать длинный ответ, затем успешно выполнить новый запрос |
| Папка с пробелами | Повторить запуск из пути, содержащего пробелы; проверить лог и сохранение |
| Изоляция | Контейнерные задачи используют локальные образы, не скачивают пакеты и не исполняют код на хосте |

7. Запишите версии Windows, Docker/WSL, Python, Flet, Ollama, точные модели, RAM/GPU, source commit, hash bundle и результат каждого сценария. Приложите журнал ошибок без частных документов.
8. Только после этой проверки передайте папку обычному пользователю. В текущей подготовке на macOS выполнены тесты логики и документа, но нативная Windows-приёмка остаётся обязательной.

## 25 Обновления, ограничения и официальные сведения

Локальная работа не требует облачной модели. Обращения модели приложения направлены на 127.0.0.1:11434/v1, а контейнеры запускаются без сети. При подготовке администратор может явно скачать компоненты; это отдельный этап. Не выбирайте облачные теги моделей и не меняйте локальный endpoint на внешний.

Полный комплект пока не является подписанным установщиком MSI/Setup. Исполняемый launcher компилируется на Windows и не переносится отдельно от каталога. Пакет исходников для сборки не равен готовому runtime-пакету. Подпись EXE, управление обновлениями, корпоративное развёртывание, проверка антивирусом и окончательная Windows-приёмка выполняются перед широким распространением.

Системные требования поставщиков могут меняться. Ниже первичные источники, проверенные при подготовке руководства. Используйте их на стадии подготовки с сетью; для офлайн-пользователя нужные компоненты должны уже быть в комплекте/системе.

- Ollama на Windows, хранилище моделей и варианты установки: https://docs.ollama.com/windows
- Docker Desktop для Windows, WSL и требования установки: https://docs.docker.com/desktop/setup/install/windows-install/
- Переносимые Python-дистрибутивы, используемые uv: https://docs.astral.sh/uv/concepts/python-versions/
- Установка пакетов в явно выбранный Python через uv: https://docs.astral.sh/uv/pip/environments/

Организация отдельно проверяет применимые условия использования Docker Desktop и лицензии моделей/библиотек перед передачей. Руководство не заменяет её решение по лицензированию и правилам информационной безопасности.
